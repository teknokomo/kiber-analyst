# План: Kiber-analyst 0.2.0 — коннекторы GitHub/GitLab/GitVerse

## Контекст

ТЗ `memory-bank/TZ_KIBER_ANALYST_0.2.0_(2).md` (v1.1): расширить read-only конвейер Kiber-analyst с Telegram-корпуса на обсуждения GitHub, GitLab и GitVerse — issues, PR/MR, reviews, comments, Discussions; сохранить provenance (провайдер, репозиторий, номер, автор, дата, URL); строить embeddings; искать через существующий hybrid-поиск и MCP; инкрементальная синхронизация без дублей и без удаления истории. База: `main` = `b903782` (после PR #1). Тег `v0.1.0` не трогаем; релиз 0.2.0 — только после приёмки владельцем.

**Решения владельца (Омиса):**
- Приёмка на реальных API — после PR, самим владельцем. Токены ZCode не передаются. ZCode: моки HTTP + изолированная PostgreSQL + инструкция для реальной приёмки. Если понадобится read-only токен для отладки — отдельный запрос, передача через защищённый env-файл, не в чат.
- Ветка `release/0.2.0` от `main` = b903782, push в origin, draft PR в `main`. Прямой push в `main` запрещён. После кода и тестов → ready for review; мерж — после ревью и приёмки.

- Очередь заданий — SQLite (`jobqueue.py`); корпус — PostgreSQL через psycopg 3 (`load.py`). Базовая схема в репо — только фикстура `tests/fixtures/knowledge_base_test_schema.sql` (модуль `0001` отсутствует); миграции саморегистрируются в `schema_migrations` (`INSERT ... ON CONFLICT DO NOTHING`), раннера нет, контракт-тесты проверяют формат (`test_load_contract.py:178-190`).
- Реестр операций: `jobapi.py:18 ALLOWED_OPERATIONS`; диспетчер `worker.py:945 process()`; checkpoint/артефакты через `store.ensure_item/update_item`; состояния `waiting_retry/waiting_quota`.
- Broker (`broker.py`): команды `:32 COMMANDS`, allowlist `sources.json` (`:196 registry`, Telegram-only regex `telegram:-N:topic:M`, записи `{project, hashes}`), `:848 start` со стейджингом файлов, `:889 source_search` (требует Telegram-источник), `SEARCH_MAX_LIMIT=50` (`:50`), audit-log автоматический.

## Этап 2 — Пакет connectors (ТЗ §5, §6, §11, §12)

`src/kiber_analyst/connectors/`:
- `errors.py` — `ConnectorError(IngestError)` с `code`; стабильные коды ТЗ §12 (`UNSUPPORTED_PROVIDER`, `SOURCE_NOT_FOUND`, `AUTH_REQUIRED`, `AUTH_FORBIDDEN`, `RATE_LIMITED`, `UPSTREAM_UNAVAILABLE`, `MALFORMED_RESPONSE`, `CHECKPOINT_INVALID`, `THREAD_NOT_FOUND`, `NORMALIZE_FAILED`); в текстах — действие, не внутренние пути; никаких токенов в логах.
- `base.py` — dataclasses `ThreadRef`, `RawItem`, `RawThread`, `NormalizedThread`; Protocol `Connector` по ТЗ §5.2 (discover без полных текстов; fetch пишет сырые ответы в каталог задания; normalize офлайн и детерминирован); registry `get_connector(provider, source_id)`; общая HTTP-обвязка на httpx: пагинация `Link` (GitHub/GitVerse) и `X-Next-Page` (GitLab), пагинация до конца; retryable {429, 5xx, таймауты, сеть} с `Retry-After` / экспоненциальным backoff+jitter, max 5 попыток; non-retryable {401/403, 404 источника, 422, неверный формат}; ETag/If-None-Match для GitHub; `since`-окно с перекрытием 5 мин (ТЗ §8).
- Валидация `source_id`/thread/item-ref (ТЗ §4): `github:[host/]owner/repo`, `gitlab:host/ns/…/project`, `gitverse:owner/repo` + построители `…:issue:N`, `…:pull:N`, `…:discussion:N`, `…:merge_request:N`, item-ref `…:body|comment|review|review_comment|reply|event:<id>`; единый модуль используется коннекторами, search_core, source_overview, broker.
- `github.py` — REST issues (исключая PR по `pull_request`), comments, pulls, reviews (state APPROVED/CHANGES_REQUESTED/COMMENTED), review comments (path/line/side/commit_id, hunk ≤8 КиБ), timeline (≤200 последних в `meta.events`); GraphQL Discussions (тело/ответы, `meta.is_answer`), без scope — `unsupported` с причиной, Issues/PR продолжают; заголовки `X-GitHub-Api-Version: 2022-11-28` и др.; labels/assignees/milestone → `documents.meta`.
- `gitlab.py` — issues/notes, merge_requests/notes/discussions; system notes → `item_kind=event`, пустой text, `meta.system=true`; `scope=all`, `state=all`, `updated_after/before`; `meta.discussion_id`, `meta.position`, resolvable/resolved.
- `gitverse.py` — перед реализацией сверить актуальный API `https://gitverse.ru/docs/developers/public-api/` (WebFetch); эндпоинты ТЗ §6.3; исключение PR из issues; endpoint 404/501 → `unsupported` с точным методом/кодом, без HTML-скрейпинга и без выдачи частичного за полный.
- `normalize.py` — детерминированные `threads.jsonl`, `items.jsonl`, `manifest.json` (формат ТЗ §5.4: snapshot_sha256, thread_count, item_count, nonempty_count, skipped_empty_count, checkpoint_before/after, api_version, errors без секретов); content_hash=SHA-256; URL по §4.5 (NULL, если шаблон неизвестен).

Конфигурация: `config/connectors.example.yaml` в репо (ТЗ §11.2, без токенов); runtime — `config_path("connectors.yaml")`, валидация при старте, неизвестный провайдер → `UNSUPPORTED_PROVIDER`; токены только env `KIBER_GITHUB_TOKEN/KIBER_GITLAB_TOKEN/KIBER_GITVERSE_TOKEN`, отсутствие → `AUTH_REQUIRED`, в `.env.example`/доках/логах не появляться. pyproject: новый extra `connectors = ["httpx[socks]>=0.28.1,<1", "PyYAML>=6,<7"]`.
